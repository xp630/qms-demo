## 一、项目概述

### 1.1 项目背景

泸州老窖在分销链路业务拓展中面临B2B支付需求，需要构建统一的云账户平台来实现：
- 线上B2B支付（微信/支付宝/银行卡）
- 线下动态码聚合支付
- 资金清分
- 费用管控

### 1.2 业务架构

```
消费者 → 终端门店 → 分销链路 → 泸州老窖
   ↓         ↓          ↓          ↓
 线下购买   线下采购/转账  金融支持   系统支撑
```

业务承载系统：融营销、窖友汇、SAP、NC系统

### 1.3 核心能力

| 模块 | 能力 |
|------|------|
| 统一收银 | 对接多支付渠道，实现线上线下支付 |
| 统一结算 | 自动对账，商户管控 |
| 统一分账 | 商流+支付结合，资金管控回流 |

## 二、技术蓝图（7页）

### 第1页：云原生设计

**核心理念**：依托网商银行资金账户基础能力，构建云原生云账户平台

**云原生特点**：

| 能力 | 说明 |
|------|------|
| 容器化部署 | 应用容器化，支持快速扩缩容 |
| 微服务架构 | 业务解耦，独立部署演进 |
| DevOps流水线 | 自动化构建、测试、部署 |
| 弹性伸缩 | 根据交易量自动扩缩资源 |

**账户能力**：
- 开户：线上开户实时审核，无需强制开立网商实体银行卡
- 收单：支持微信、支付宝、银联等
- 支付：三方支付、银行卡直接支付
- 清分：按交易背景按平台指令实现清分
- 受控：资金受账户支用、冻结受控

---

### 第2页：设计思路

**使用云原生技术的好处**

| 维度 | 传统架构 | 云原生架构 |
|------|----------|------------|
| 交付效率 | 月级交付 | 周级/天级交付 |
| 资源利用率 | 固定资源，预留峰值 | 弹性伸缩，按需使用 |
| 故障恢复 | 手动恢复 | 自动故障转移 |
| 扩展能力 | 扩展周期长 | 分钟级扩展 |
| 运维成本 | 高（专职运维） | 低（平台自动化） |

**技术扩展性考虑**：
- 项目未来存在继续建设的可能性
- 技术上需要考虑后续的技术迭代和扩展性
- 使用统一的代码规范和代码管理工具

## 三、技术方案详细说明

### 3.1 云原生技术选型

| 类别 | 技术选型 | 说明 |
|------|----------|------|
| 容器编排 | Kubernetes (ACK) | 阿里云容器服务 |
| 微服务框架 | Spring Cloud / SOFAStack | 蚂蚁技术栈 |
| 消息队列 | RocketMQ | 阿里云消息队列 |
| 分布式数据库 | OceanBase | 蚂蚁自研 |
| 缓存 | Redis Cluster | 阿里云Redis |
| API网关 | Apache APISIX / Sentinel | 流量控制、熔断 |

### 3.2 安全设计

- 代码扫描：蚂蚁代码扫描
- 漏洞检测：老窖内部漏洞检测
- 安全检测：未通过项需按建议修改后再发布

### 3.3 统一技术路线

- 统一主流技术栈、中间件
- 统一代码管理工具（老窖域代码仓库）
- 保证系统技术架构先进性
